mobile app · solution design

商家端移动应用方案 · iOS + Android

把现有「商家调度台」变成双端可安装的原生应用，功能与 Web 完全一致。 本方案基于现有代码资产做选型，目标是最短路径上线，同时不给未来留下两套 UI 的维护债。

版本 v1.0 2026-10-27 适用：11 个页面 / 40+ 接口

结论：Capacitor 7 混合架构

一套 Vue 3 源码，同时打包 Android APK/AAB 与 iOS IPA。 业务代码 100% 复用，只新增「移动端适配层 + 原生能力桥接」。

不建议此时用 React Native / Flutter 重写：11 个页面、40+ 接口、ECharts 图表与 Element Plus 表格全部要重做一遍， 工期翻 4 倍，且从此维护 Web 与 App 两套界面代码。

必须解决的 8 个技术点

问题做法
接口地址构建时注入 VITE_API_BASE 指向生产域名；Web 端仍走 /api 相对路径（nginx 反代）
跨域 CORS放行 https://localhost / capacitor://localhost，否则 App 内全部 403 高危
登录态存储Web 用 localStorage；App 内改加密存储（Android Keystore / iOS Keychain），避免明文
订单推送Android 国内必须接厂商通道（华为/小米/OPPO/vivo）→ 直接用极光 / 个推，一次覆盖双端；iOS 走 APNs
语音播报部分安卓 WebView 无中文语音包 → App 内改用原生 TTS 插件
批量导入原生文件选择器 + 读取，Excel 解析逻辑不变
返回键非首页 → 路由后退；首页 → 二次确认退出
热更新只热更 Web 资源；原生依赖变更仍走商店发版
